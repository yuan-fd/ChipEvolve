# OpenROAD 自演化 EDA 平台 v2.0 实施与验收报告

验收日期：2026-08-23。本文是对 `v2.0_审计与升级规划_待审批.md` 的实施状态补充；历史规划和原始资料均保留，未删除。

## 结论

v2.0 的控制平面、安全门禁、RTL 候选谱系、可审计数据接口、TaiWei 边界与基础工作台已经实现并通过常规全库回归。平台现在不会把 LLM 文本、lint 成功、单次 QoR 或静态图片误称为功能正确、可演化成功或任意工艺支持。

仍不能宣称“任意自然语言设计均已跑通”或“PPA 有显著提升”：这需要冻结的设计级仿真/形式 oracle、真实 ORFS 多 seed 基准矩阵和独立复测。当前工程已为这些实验设置了 fail-closed 门，而不是伪造结论。

## 已实施能力与验证

| 计划 | 实施 | 验证 |
|---|---|---|
| 四道门 | append-only Experiment Graph；baseline→observation→proposal→review→attempt→measurement→decision→memory；只允许已审参数 action 提交 Runtime；写操作按 baseline owner 授权。 | `test_experiment_graph.py`、`test_four_gate.py`、API owner 测试通过。 |
| RTLScout-v2 前端边界 | `SpecIR`、`VerificationPackage`、`RTLCandidate` 和不可变 SQLite 谱系；RTL verify 插件在隔离 workspace 中执行 Verilator/Yosys；Runtime 回写 compile/lint 证据。 | RTL contracts/store/plugin 测试通过。 |
| 正确性→PPA 门 | ORFS promotion 必须具备同一候选的 compile/lint 以及 simulation/formal/equivalence 通过记录。新增 `rtl-sim`，以哈希锁定的冻结 testbench 运行固定 Icarus 编译/仿真；默认 bootstrap 路径没有 oracle，因此被明确阻止晋级。 | compile-only promotion fail-closed、testbench 篡改失败、Runtime 回写 simulation gate 测试通过。 |
| Oracle 接入 | `POST /api/rtl/specs/{id}/simulation-oracle` 冻结用户审核的 testbench，创建继承父候选的新 package/candidate；`/simulate` 仅接受该 content-addressed oracle。 | child lineage、SHA/provenance 与工具未就绪 fail-closed 路径测试通过。 |
| 形式验证 | `rtl-formal` 使用 frozen property harness + Yosys `sat -prove-asserts` bounded proof；property oracle 派生 candidate，Runtime formal report 回写 `formal` gate。 | 真实本机 Yosys SAT proof、formal/API/front-end 测试与全库回归通过。 |
| 后端反馈 | candidate-linked ORFS terminal run 自动写回不可变 `ppa` check，与泛化 learning observation 分开；单次 terminal success 不产生“显著优化”结论。 | Runtime terminal artifact→candidate PPA evidence 测试通过。 |
| 代码级演化准备 | `PatchRegistry` 以 SQLite 保存 immutable patch SHA、base commit、evidence、patch surface 与固定 argv validation policy；`ApiState` 持有独立 registry DB。 | registry rehydrate/integrity、应用初始化回归通过；尚未开放自动 apply/merge 或任意命令执行。 |

`tool_code` 的 `ActionSpec.patch_ref` 只能是 `artifact:patch-registry:<sha>`；外部路径、普通 artifact 和任意 shell 文本都不能成为代码级动作输入。
| Agent/学习安全 | Agent 输出只能成为 proposal；Runtime 是唯一执行和终态权威；decision/memory 可记录 promoted、negative、rejected、no_improvement，避免幸存者偏差。 | 四道门决策/记忆边测试通过。 |
| 证据型长期记忆 | Four-Gate decision/memory 会投影到按 owner 隔离的 Evidence RAG；每条记录绑定规范化 Runtime 运行摘要的 SHA。Runtime terminal fact 才能是 verified/可作提案证据；人工 rationale 一律只作为不可执行的 hypothesis 或 failed_attempt。 | 端到端基线→动作→测量→决策→检索测试通过，并验证另一 owner 不能读取；`execution_allowed=false`。 |
| EDA→AI 数据接口 | `DesignIR`、`RuntimeEvidenceIR` 和 bounded evidence cards；均为事实投影、`action_eligible=false`。 | DesignIR/RuntimeIR/API 测试通过。 |
| TaiWei 3D | 增加机器可读技术矩阵，仅列 `asap7_3D`、`nangate45_3D`、`asap7_nangate45_3D`；显式声明不覆盖 arbitrary PDK、signoff DRC/STA、thermal/IR signoff。 | TaiWei 适配器与矩阵测试通过。 |
| GUI/可视化 | 模块接口图来自 DesignIR；门级图来自综合网表连接投影；前端可在 module/gate/RTL/netlist 间切换。 | 视觉/API/web 回归通过。 |
| 测试卫生 | `pytest.ini` 固定 `testpaths=tests`，默认跳过 `real_3d`，避免 runtime workspace 内上游测试被误收集。 | 首次全库发现并修复收集冲突；重跑通过。 |

被 deselect 的 `real_3d` 是真实 TaiWei E2E，按策略只应在串行、资源锁定、固定工具链的 nightly 环境显式执行：`pytest -m real_3d`。它未在本次普通回归中被作为成功证据。

## 当前剩余的实验/工程工作

1. 将 RTLScout 的 benchmark-only 上游输入改为真正的 `SpecIR + frozen testbench/SVA/formal` 生成器，并针对 gcd、ibex 配置、UART 等建立可复放 suite。
2. 实装受控 simulation/formal/equivalence Runtime plugins；在这些 oracle 未接入前，功能 RTL 不可进入 ORFS，属于刻意的安全边界。
3. 用同 PDK、同 toolchain、同 seed protocol 的 ORFS 多重复测报告 PPA、时间、失败率与置信区间；不能以单次最优点证明优化。
4. 将 DPLEvolve 保持在 source-lock/read-only 审计状态，待 patch surface、隔离编译、差分全流程与人工 promotion gate 全部可复放后再开放代码级演化。
5. 拆分 `apps/api/app.py` 和 `apps/web/assets/app.js` 的多职责耦合；当前新增领域逻辑已优先置于 contracts/scheduler/analysis/visualization，但 HTTP composition 仍偏大。
6. 将目前的模块/门级 SVG 继续升级为可交互 hierarchy/网表浏览器，并把 OpenROAD GUI 的受控只读会话接入为独立功能；目前不把静态图包装成 Vivado/KLayout 级 GUI。

## 2026-08-24 缺口补齐记录

- 固定 v2 前端 suite 新增 `scripts/run_v2_frontend_suite.py`，支持每个 gcd/FIFO/UART/ibex package 的重复编译、PASS 仿真和 Verilator lint，并输出 golden/Testbench 哈希和日志。本轮实际执行 4×3=12 次，三类门全部通过。
- `export_netlist_to_circuitops()` 将已登记综合网表导出为完整 CircuitOps v1 表 schema；没有观测到的 library/physical 属性保持空表，不填默认值。`POST /api/designs/{id}/circuitops-export` 通过设计所有权校验后生成可重建的只读投影。
- 新增 CircuitOps 导出、前端 suite runner 和 API 相关回归测试；这些测试证明接口和固定基线可复放，不把 golden fixture 误称为 LLM 生成质量或 PPA 改善。
