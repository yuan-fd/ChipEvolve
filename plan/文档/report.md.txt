## 四、架构分析

### 4.1 调用链

用户执行 CLI
    ↓
run_benchmark.py（单次运行入口）
    ↓
core/runner.py → run_agent_on_benchmark()
    ├── core/agent.py（ReAct Agent 循环）
    ├── core/llm_client.py（LLM API 调用）
    ├── core/correctness.py（Verilator 验证）
    ├── core/cost.py（成本评估）
    └── core/evaluation.py（综合评估）
    ↓
输出：runs/<benchmark>/<model>/result.json + best_design/

### 4.2 阶段分解

| 阶段 | 输入 | 处理 | 输出 |
|------|------|------|------|
| 输入阶段 | Benchmark 规格、LLM 配置、成本指标 | 加载 benchmark 元数据 | 初始化 Agent 上下文 |
| 初始化阶段 | Agent 上下文 | 构建 System Prompt、创建工作区 | 就绪的工作区 |
| 迭代优化阶段 | 工作区状态 | LLM 推理 → 工具调用 → 验证 → 评估 → 更新 | 更新后的工作区 |
| 输出阶段 | 最优设计 | 写入 result.json + best_design/ | 最终产物 |


## 五、黑箱视图（给平台调度器）

### 5.1 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| --benchmark | string | ✅ | benchmark 目录名 |
| --model | string | ✅ | LLM 模型 |
| --cost-metric | string | ❌ | transistors / area / delay / power |
| --language | string | ❌ | verilog / spirehdl / amaranth |
| --max-steps | int | ❌ | 最大迭代步数，默认 20 |

### 5.2 输出

| 产物 | 路径 | 格式 |
|------|------|------|
| 结果 JSON | runs/.../result.json | JSON |
| 最优设计 | runs/.../best_design/ | .v / .py |

九、部署验证记录
9.1 鲲鹏 ARM64 服务器尝试
执行 pull_image.sh 拉取预构建镜像成功

执行 start_container.sh 启动失败

报错：exec /usr/bin/bash: no such file or directory

原因：镜像架构为 amd64，与 ARM64 不兼容

9.2 WSL x86_64 环境尝试
环境：WSL2 Ubuntu + Docker 29.1.3

成功拉取镜像并启动容器

执行冒烟测试通过
Best: PASS | 308 transistors (step 1) | Steps: 3 | Duration: 38.13s

9.3 结论
RTLScout 可在 x86_64 环境下正常部署运行。鲲鹏 ARM64 环境因官方镜像架构不兼容暂不可行。
