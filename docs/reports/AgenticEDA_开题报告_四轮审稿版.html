摘要：这个课题到底要解决什么

OpenROAD 已经能完成从综合、布局、时钟树、布线到 GDS 的开放流程，但它面对的是脚本、参数和大量工程报告；大语言模型擅长理解自然语言，却不能靠“说得像专家”证明电路正确、PPA 变好或修复没有副作用。本课题的目标，是在两者之间建立一个可靠的实验系统：大模型负责理解、规划、提出假设和解释，受保护 Runtime 负责执行；在已经接入且能产生receipt的验证门上，Verilator、Yosys、OpenROAD和当前DRC/时序检查负责判定；更强的LVS、CEC/formal和3D fresh-signoff属于按条件或后续接入能力。证据数据库负责追溯，受控实验和留出设计负责检验经验能否迁移。

用大白话说，平台不是让 AI “替工程师按几个按钮”，而是让它像一个受实验制度约束的研究团队：写 RTL 的人不能改试卷，写试卷的人不能给自己判分；优化器只能提出下一组值得测的参数，不能把预测值冒充真实 PPA；一次成功只能记为一次观察，不能直接升格为规律；跨设计复验失败的经验也必须保存，用来阻止下一次犯同样的错。

核心研究问题具体问题怎样才算回答了
RQ1：自然语言到 RTL怎样把不严谨的需求变成端口、时钟、复位、行为和验收条件明确的规格？RTL作者和Testbench作者怎样分离？固定题与开放规格、多seed；报告编译、功能、mutation、coverage/formal、成本和后端PPA，保留所有失败。

RQ4：深层自演化系统怎样从“记住成功配置”升级为带机制、反证条件和迁移边界的知识？局部受控干预、效应与不确定性、预注册holdout、正负迁移知识卡；做真实四臂消融。

一、平台定位与最终工作流

平台位于自然语言需求与 OpenROAD 工具链之间。它不是替换 OpenROAD，而是给现有 EDA 工具增加四层能力：设计意图合同、Agent实验控制、EDA证据接口、可复验知识循环。最终用户给出自然语言规格，平台自动完成规格结构化、测试生成、RTL候选演化和前端验证；通过的 RTL 进入 OpenROAD，先得到共同 baseline，再由 BO/GP 和 Agent 在预算内做参数组合实验；连续三个批次没有可靠改善时，平台冻结搜索轨迹并把诊断包交给 Repair Agent；后者只能提出白名单动作，所有动作都由 Runtime 执行并重新验收；经过局部干预和留出设计复验的经验进入知识库，影响下一轮提案。

图1　最终目标工作流。图按参考图风格分成三条大泳道，每个框均写明输入、处理和输出。底部思考链不是隐藏的“思维过程文本”，而是八类可审计结构化事件。

1.1 两条闭环怎样衔接

  1. 前端正确性闭环：自然语言→SpecIR→职责与写权限独立的Verification Agent→冻结Testbench→RTLScout候选→compile/lint/simulation/mutation→合格RTL。这里“独立”不是独立模型：当前Verification与RTL角色都由同一托管模型 gpt-5.6-terra 执行。
  2. 后端QoR闭环：合格RTL→共同baseline→EDAIR/CircuitOps证据→BO/GP组合提案→真实OpenROAD实验→统计审查→停滞换向→受限动作→复测→知识准入。
  3. 共同原则：两个闭环都使用受保护评估器。候选生成者看得到错误反馈，但无权修改判分工具、原始报告和准入门。

1.2 PPA偏好不是空按钮

用户选择“平衡 / 面积 / 时序 / 性能”后，系统把偏好转换成版本化 objective_profile：每个指标有方向、权重、归一化基准和硬约束。偏好只影响候选排序，不能覆盖安全门。例如“面积优先”可以提高 area 权重，但 setup WNS、DRC、失败率等硬约束仍必须通过。当前轻量实现采用加权标量效用；论文目标将同时报告 Pareto 前沿和 hypervolume，避免一组权重掩盖真实取舍。

u(x)=Σ wi·si(x)，其中 si 先按 baseline 与目标方向归一化；若任何硬约束失败，则候选不可行，不参与“更优”排名。

二、Agent如何规划、执行与受约束

本平台采用“一份执行权，多种提案角色”。Spec、Verification、RTL、Optimizer、Repair、Reviewer 和 Memory 角色可以各自生成结构化产物，但只有 Runtime 可以启动插件和命令，只有固定评估器可以写入终态指标。这样做不是为了让架构图看起来复杂，而是为了把冲突职责分开：提出假设的人不能直接把假设变成事实，修改候选的人不能修改验证器，保存知识的人不能跳过复验。

2.2 当前Agent架构证据支持到哪里

8月25日四设计真实闭环 trace 均出现八个核心阶段；FIFO、UART 完成闭环，GCD、ibex_alu 正确进入 diagnosis_required。同时存在 baseline/candidate 部分提交恢复、终态幂等、非法 clock 参数拒绝和浏览器越权字段拒绝测试。这证明状态机、checkpoint和权限词表能够工作；但现有审计主要检查事件标签和字段自洽，尚未完成 flat agent / no Judge / no checkpoint / full architecture 的同预算消融，因此不能说“多Agent已经提高QoR”。

三、RTL生成：把RTLScout内部完整拆开

RTLScout 不是一个可以用名字遮住细节的黑盒。它在平台中承担的是“候选演化控制器”：根据规格和验证反馈管理候选树，使用受限文件工具修改 RTL，调用固定 evaluator，比较功能和成本，再决定保留父候选、修补或开新分支。Testbench 由另一个 Verification Agent 自动生成并冻结；“独立”指职责、提示、工作区和写权限分离，不代表当前使用两个不同模型——两种角色目前都由平台托管的 gpt-5.6-terra 执行。

图2　Testbench作者、RTL作者和评估器三方分离。红色反馈有两种：RTL功能错误返回RTLScout；测试检错能力不足返回Verification Agent。图是最终方法框架；当前证据只达到固定四题各单seed可执行性演示。

3.1 从用户输入到冻结规格

  1. 用户给出任意自然语言需求，不要求属于 gcd/FIFO/UART/ibex 题库。
  2. Spec Agent 抽取 top module、端口方向、位宽、时钟/复位、握手时序、状态行为、异常行为、PPA偏好和硬约束。
  3. 无法确定的内容进入 open_questions；可以安全假设的内容写入 assumptions，不能悄悄补全。
  4. 生成机器可读 SpecIR 和给人看的规格摘要。固定四题只是回归测试集，用于防止平台修改后能力退化，不是输入白名单。

3.2 Testbench、Oracle和RTLScout是什么关系

大白话解释：Testbench 是“考试程序”，负责给电路输入并检查输出；Oracle 是“判对判错的依据”，可能是reference model、scoreboard、断言或协议规则，不一定是一份golden RTL；RTLScout 是“做题并根据错题反馈修改答案的人”。自动化要求Testbench也由机器生成，而不是每次请人写，但自动生成不等于可以自证正确，所以必须用mutation、coverage、形式属性或参考模型检查试卷够不够强。
检查层具体做什么能证明什么不能证明什么
Compile / elaboration模块、端口、参数、SystemVerilog语法能否展开文件结构合法功能正确
Verilator lint位宽、未驱动、锁存、不可达、时序语义等静态问题发现一类常见编码风险所有输入序列都正确
Yosys check / synth网表可综合、多驱动、组合环等可进入综合及基础结构检查与规格等价
Functional simulation冻结TB产生输入，scoreboard/SVA检查输出测试覆盖到的行为通过未覆盖行为正确

3.3 RTLScout一次迭代的具体算法

  1. 初始化：加载 SpecIR、冻结 VerificationPackage、parent/elite候选、workspace、max steps和token预算。
  2. 计划：模型先选择修语法、修功能、降低结构成本或开新分支，输出结构化意图。
  3. 受限编辑：只允许 list/read/create/replace/diff 候选RTL，不允许shell、网络、修改TB或评估器。
  4. 快速门：Verilator/Yosys 做compile/lint/synthesis；失败返回文件、行号、类别和有界原文。
  5. 功能门：冻结TB仿真；如有条件再执行SVA/CEC。RTL失败只返回给RTL作者。
  6. 测试质量门：计算 killed/executable，同时报告 generated、invalid、survived；invalid比例过高应拒绝质量声明。
  7. 成本门：只有功能通过候选才能比较Yosys/ABC cost；这只是前端代理成本，最终PPA必须由OpenROAD重测。
  8. 选择：更优候选写入archive并记录parent→child、RTL SHA、生成模型和评估receipts；不更优则保留parent并继续。
  9. 晋级：独立Runtime重新跑compile/sim/mutation，合格后才允许启动OpenROAD baseline。

这组结果可以安全声称：四个固定规格各一个生成seed，从自然语言、自动Testbench、RTLScout、lint、仿真、mutation一直跑到非空GDS，证明固定suite的端到端可行性。它不能证明“任意自然语言都能生成”、不能给出多seed成功率，也不能把“RTL和TB字节不同于golden fixture”当作功能等价证据。下一轮必须增加开放规格、多模块设计、每题至少5个模型seed、reference model/coverage/formal，并核验候选SHA唯一性和真实lineage。

四、EDA-to-AI数据接口：AI实际读的是什么

AI不应该只读一段手工摘要，也不应该把数百MB日志全部塞进上下文。前者会丢细节，后者超出上下文并让噪声淹没信号。平台采用“原始权威层＋专用parser＋Typed IR＋关系图/表＋分级EvidencePacket”架构：摘要用于导航，对象用于定位，原文片段用于核验；每层都保留回到原artifact的指针。

图3　低失真并非不压缩，而是“压缩造成的损失可见，重要事实可按ID回读”。逻辑netlist连接与物理DEF/ODB网络必须分开命名，避免把逻辑对象冒充物理对象。

4.1 五层数据结构

  1. 原始层：RTL、脚本、log、report、netlist、SDC、Liberty、DEF、ODB、SPEF、GDS。登记 SHA-256、大小、类型、run/stage、工具commit和flow seed。
  2. Parser层：OpenROAD metrics/stage JSON、OpenSTA timing block、DEF component/net、netlist连接等专用解析器；每个parser有版本、单位、source span、未解析块和截断状态。
  3. Typed IR层：Run、Stage、Event、Metric、TimingPath、TimingPoint、Instance、Net、Violation、Connectivity。不存在的信息保持 null/unknown。
  4. 图与表层：CircuitOps cell/pin/net property tables与edge tables；稳定主键、row count、表hash和跨artifact实体关系。
  5. Agent查询层：L0 KPI→L1阶段→L2对象/子图→L3原文片段。每个EvidencePacket带 loss_manifest、artifact目录和query trace。

当前EDAIR消融的正确说法：它证明比12项KPI摘要提供了更多可查询对象和provenance；不能据此声称“低失真已经验证”或“Agent诊断更准”。现有 loss_manifest.timing_paths=0 只表示已解析列表没有因packet上限再次截断，不代表parser没有漏掉原报告路径。真正的保真度要看 parser_fidelity.unparsed_blocks，并与原报告、DEF/ODB做抽样或round-trip核验。

4.3 与 CircuitOps、EDATracer 的关系

CircuitOps（ICCAD 2023）把电路转换为可供ML使用的属性表与关系表，提供 cell/pin/net 图式基础；EDATracer（2026预印本）进一步把source、scripts、logs、netlists、reports组织为知识图谱和语义向量索引，在18.9GB、2,787个可综合设计、90问benchmark上报告跨artifact问答结果。平台借鉴的是“结构图＋语义索引＋逐句证据回链”，但不能照搬其规模数字当作自己的成绩。我们的研究任务是建立OpenROAD专用实体/关系schema和诊断题集，比较 raw / summary / EDAIR / graph+vector 的准确率、证据率、遗漏、token与延迟。

五、BO与GP怎样探索组合参数

贝叶斯优化的作用不是直接把芯片“算好”，而是减少昂贵的OpenROAD试验次数。它根据已经测过的参数组合拟合代理模型，估计未测组合可能有多好、模型有多不确定，再选择下一组最值得真实测量的点。参数组合必须整体输入模型，因此它可以学习 core_utilization × place_density 这类组合效应；一次只改一个参数只能做局部敏感性分析，不能替代组合搜索。

图4　上半部分给出一次BO迭代的数学和数据流；左下是完整campaign与停滞换向；右下直接写出8月25日实验的证据和方法学缺口。

5.1 当前轻量算法：精确到可复现参数

  1. 只接受同一design fingerprint、PDK、tool commit、stage和parser版本的观测；研究预算由 study.max_runs 限制。
  2. 连续参数按上下界映射到[0,1]。每轮使用 study.seed + iteration×1009 初始化随机数，在每个维度生成512点确定性Latin-hypercube候选池；与已测点最大坐标差≤1e−8的点删除。
  3. 相同参数向量的成功重复先分组；每个目标以组均值训练，观测噪声取样本方差除以组大小。当前实验没有真实改变flow seed，因此该方差会错误地接近0。
  4. 每个目标拟合exact RBF GP：length scale=0.35，基础jitter=1e−6；Cholesky失败时最多把jitter逐次放大10倍共8次。核超参数当前不从数据学习。
  5. 每个目标按已观测组均值的min/max缩放，max目标用 (μ−min)/(max−min)，min目标用 (max−μ)/(max−min)；range≤1e−12时scale取1。权重除以总权重后合成效用均值，方差按独立目标平方加权。
  6. Expected Improvement使用 ξ=0.05。失败/不完整观测不训练QoR GP，但以长度尺度0.20的局部核和Beta(1,1)平滑估计经验可行概率，最终采集值为 EI×P(feasible)。
  7. 使用 numpy.argmax 选择采集值最大点；完全并列时选择候选池中第一个。成功完整观测少于2条时选择LHS池第一个点，采集值记0。
  8. 硬约束在调度/验收层执行：setup WNS≥0、has_drc_errors=false。当前 balanced 权重为timing 0.40、area 0.35、power 0.25；单目标profile权重为1。
I(x)=μ(x)−ubest−ξ；z=I(x)/σ(x)；EI(x)=I(x)Φ(z)+σ(x)φ(z)。σ大代表模型不确定，鼓励探索；μ好代表可能改善，鼓励利用。

论文目标不是把当前实现包装成高级MOBO，而是明确升级：连续/整数/类别混合编码、Sobol/LHS warm start、失败/超时可行性模型、真实异方差噪声、qNEI/qNEHVI、Pareto archive、hypervolume和trust-region/全局重启。

5.2 停滞怎样判定，为什么是三轮

每个batch结束后更新best-so-far和Pareto集合。连续三个batch的改善低于预注册实用阈值，且置信区间不支持可靠改善时，才判为停滞。三轮是工程默认值，不是自然定律，必须在协议中固定并做敏感性分析。停滞后先改变参数子空间、采集函数或目标权重；仍无改善再输出stage diagnosis packet交给Repair Agent。Repair Agent不是直接改源码，而是提出“假设—证据—动作—预期—停止条件”的ActionSpec。

5.3 8月25日BO对随机实验究竟说明什么

现有汇总包含4设计×3 optimizer seed标签；BO和seeded random各144个terminal run，预算相等。设计级中位数胜负为2:2：UART和ibex_alu的BO中位数较好，GCD和FIFO的随机搜索较好。达到0.5%阈值的design-seed单元是BO 7/12、random 4/12。这是有价值的描述性证据，但还不是统计优越性证明。

必须修正的实验设计：当前每配置三个 replica_index 没有把不同工具flow seed传给ORFS，因此同一角点常得到完全相同的PPA；IQR=0不是“平台很稳定”，而是伪重复。BO首个seed为20260824，random首个seed为20260825，也不是严格配对。当前优化器代码会按相同参数聚合重复点，不会把三条baseline简单当成三个不同X；但伪重复仍使组内方差估计为0，只剩1e−6基础jitter，GP依旧会过度自信。正式论文实验必须使用共同baseline、配对policy seed、真实不同flow seed、anytime AUC/regret和层级bootstrap/permutation。

六、自演化：从运行事实到可复验知识

只记录“这次参数成功了”不是学习，因为系统不知道成功发生在什么设计、工艺、工具版本和约束下，也不知道是哪一个因素起作用，更不知道换一个设计是否反向。真正的自演化至少包含四级：观察事实、提出机制、受控干预、跨设计复验。RAG仍然有用，但它负责找到相关材料，不负责证明材料正确；外部论文和DPLEvolve知识只能作为先验和实验灵感，不能直接成为自动动作规则。

图5　知识准入的完整目标链路。Observation、Hypothesis、Controlled Intervention、Holdout和Knowledge Card是不同状态，不能用一次LLM总结跨级。当前真实证据只有一个负迁移门控演示，不是真实四臂学习消融。

图6　左侧是知识卡字段，右侧是GCD→FIFO真实反例。该例没有“学到一个调参秘诀”，而是学到“这条组合规律不能跨这两个设计直接复用”。

6.1 知识生命周期

Observation → Draft Hypothesis → Pre-registered Intervention → Supported/Refuted on source → Held-out Validation → Validated/Negative-transfer → Planner引用 → 新运行复验 → 更新/撤销/退休。

知识卡必须保存context key、重复统计、claim、mechanism、intervention、falsifier、不确定性、run/artifact/protocol指针、生命周期和权限。action_eligible 表示这条知识可以给规划器作为候选依据；execution_allowed 仍然为false，真实动作必须重新走提案和Runtime门。

6.2 组合条件怎样用2×2实验识别

以参数A和B各取低/高两个水平，得到四个角点。B在A低时的效果与B在A高时的效果之差，就是difference-in-differences交互项：

interaction = [Y(Ahigh,Bhigh)−Y(Ahigh,Blow)] − [Y(Alow,Bhigh)−Y(Alow,Blow)]。

该方法能区分“两个参数各自有效”和“必须组合才有效”，但只有在每角真实独立重复、随机化执行顺序、报告方差/CI、预先规定最小效应阈值时，才具备统计解释。当前代码用 abs(effect)>1e−12 判非零过于宽松，任何数值噪声都可能被当成局部支持，必须改成效应量＋不确定性门。

6.3 当前GCD→FIFO反例

在GCD中，core_utilization_pct × place_density 对 instance area 的局部interaction为+1.862；按预注册合同换FIFO复验后变成−1.596，方向反转。系统将知识卡标为 refuted、promoted=false、action_eligible=false，并生成 Teacher guidance：不得把源设计交互当作通用规则，先解释设计特征差异，再做第三设计确认。这证明准入门能够阻止一次具体负迁移。

但这还不是“达到前沿深层因果学习”：三个replica仍是伪重复；没有方差、CI和效应阈值；只做了一个source→holdout对；指标是instance area，机制还需核验网表/缓冲单元变化。现有learning ablation也是脚本构造的counterfactual policy audit，而非四套策略真实跑同任务：rag_only会误迁移是脚本定义，不是实际RAG→Planner→EDA执行结果。正式消融必须让no-memory、RAG-only、observed-memory、causal+holdout四臂在多组leave-one-design-out任务上真实运行。

6.4 DPLEvolve知识库可以补什么

已获取的DPLEvolve副本包含多层知识，而不是只有Acknowledgement：placement/legalization/DPO算法说明，OpenDP论文与paper source索引，mechanism stack cards与skill cards，指标合同、证据政策、Teacher-child跨案例实验合同，以及dense legalizer、cut-row、runtime、handoff、source-level mechanism等案例笔记。适合用作Teacher预热、机制候选和停止条件模板。

十、TaiWei3D当前状态与研究边界

TaiWei3D是一条相对独立的3D IC研究线。当前平台能够维护固定官方链路和单例证据，但没有足够数据支持“任意工艺、任意设计都能跑通”。工艺可移植性不仅是更换LEF/Liberty：还涉及tier定义、bond/via规则、跨层寄生与时序、router能力、脚本假设和signoff工具。每新增工艺必须逐项验证数据文件、层映射、3D对象生成、阶段执行和最终门。

11.1 统计报告最低要求

  • 预注册设计、指标、硬约束、实用提升阈值、seed、预算、停止规则和排除规则，并保存协议hash。
  • 同一配置的重复必须真正改变工具flow seed；LLM seed与EDA seed分别记录。
  • 报告全部terminal runs、失败率、中位数、IQR、范围和bootstrap置信区间；配对设计使用配对检验或层级模型。
  • 序贯优化报告best-so-far曲线、AUC/regret和预算到达率，不只比较最后最好点。
  • 多目标报告Pareto/hypervolume和硬约束；单次最好值只能作为示例，不能写“显著优化”。
  • 外部论文规模、成功率和QoR改善必须标为“作者报告”，不得与本平台实验混表。

十二、实施阶段与里程碑

图只展示最终架构；实施按依赖关系分四个阶段，不提前开发尚无上游证据支持的功能。

  1. 阶段A·可信主链：修复真实flow seed、配对实验、候选lineage、mutation invalid门、parser保真和真实学习消融；使自然语言→RTL→baseline→N轮探索→停滞→诊断→知识闭环具备论文级证据。
  2. 阶段B·有限动作单工具：逐个接入Timing ECO、物理感知重综合、EvoDRC和来源/许可合格的源码演化器；每个工具独立完成ActionSpec、sandbox、fresh verifier、rollback和多设计验证。
  3. 阶段C·跨阶段组合：研究不同动作顺序、checkpoint继承和full-flow composability，识别局部改善在下游消失或反转的条件。
  4. 阶段D·规模化生态：多设计、多PDK、多seed和开放任务持续运行；建立公开benchmark、诊断题集、模型/工具版本基线和可重复论文包。

十五、结论

本课题的创新点不在于发明更多Agent名字，而在于把自然语言RTL生成、OpenROAD全流程、低失真EDA证据、组合参数搜索、停滞换向、有限动作和知识复验放进同一份受保护实验合同。当前平台已经证明主链能在四个固定设计上真实执行，并具备留下run、artifact和决策trace的基础；也已经暴露出最关键的科研缺口：独立随机重复、强验证、多任务真实消融、数据保真和跨设计统计。

因此，下一阶段最有价值的工作不是继续扩张功能名录，而是把这些缺口补成不可辩驳的证据。完成后，平台可以合理支撑一篇以“可信AgenticEDA闭环基础设施与消融”为主题的论文；TimingECO、EvoDRC、重综合和源码演化器等工具应在主链验收后逐个接入，再研究它们能否形成完整生态。
