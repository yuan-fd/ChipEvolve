一、综合是干什么的？—— 把"图纸语言"翻译成"零件清单"

综合（Synthesis）是整个流程的起点：输入是 RTL 代码（描述芯片行为："这个模块应该算什么"），输出是门级网表（描述芯片结构："用哪些门、怎么连"）。

打个比方：RTL 是建筑师的设计意图（"这里要一堵承重墙，那里要一个客厅"）；综合就是施工图设计（"用 200 块标准砖、12 根钢筋，按这张图砌"）。门级网表就是那张施工图。

综合要遵守两本"法规"：

  • 工艺库（.lib）：这家工厂只有这些"标准零件"（AND 门、OR 门、触发器…每个多大、多快、多费电）；
  • 时序约束（SDC）：芯片要在多快时钟下工作、哪些路径必须准时。

所以综合的完整答案 = 行为翻译 + 逻辑化简 + 用规定的零件拼出来 + 保证能跑得动。

二、综合的四步内部流程

① RTL 解析→ ② 行为综合→ ③ 逻辑优化→ ④ 工艺映射
子步骤大白话输出
① RTL 解析（elaboration）把 Verilog 读进来，理解每个模块、每个 always 块、"展开"成电路结构内部电路表示（还没用具体门）
② 行为综合把"行为描述"变成"逻辑表达式"：加法器展开成一位位全加器、多路选择器展开成逻辑门、状态机编码与工艺无关的逻辑网络
③ 逻辑优化用布尔代数化简：A·B + A·¬B = A 这种合并；去掉多余逻辑，减少门数/深度化简后的逻辑
④ 工艺映射把化简后的逻辑"翻译"成工艺库里的真实单元（AND2 门、NAND2 门、DFF…），并做时序优化门级网表
关键认识：③④ 两步才是综合的"灵魂"，也是最难的部分——它们由 ABC 这个工具完成（见下节）。这也是为什么老师资料里会反复出现"ABC"。

三、ABC 是什么？—— 逻辑综合的"数学大脑"

ABC（berkeley-abc，github.com/berkeley-abc/abc）是加州伯克利大学开源的一个逻辑综合与验证工具，几十年来学术界和工业界都在用。Yosys 把最难的逻辑优化和工艺映射外包给它。

ABC 内部干的事（都是数学）：

  • AIG 表示：把所有逻辑表示成"与门 + 反相器"的图（And-Inverter Graph）——一种统一、好优化的数学形式；
  • 布尔优化：在 AIG 上做化简（节点合并、冗余消除），目标是面积小或延迟短；
  • 工艺映射：把 AIG 的节点"覆盖"成工艺库里的门（每个门覆盖一小块图），像拼图一样；
  • 时序驱动：结合单元延迟，让关键路径尽量短。
你听到的"ABC 对齐"大概指：用 ABC 把 RTL 综合出来的逻辑，对齐/映射到某个工艺库的单元集合上（"对齐"= 映射、适配）。老师发的西门子资料里讲综合时，也会讲同样的概念——只是工业工具把 ABC 的逻辑封装在内部。

一句话：ABC = 逻辑综合的数学引擎（化简 + 映射），Yosys 是它的"外壳"（负责读 RTL、管理流程、输出网表）。

四、Yosys 和 ABC 怎么配合（附真实命令）

ORFS 的综合阶段实际执行的 Yosys 脚本（简化版）：

# 1. 读入 RTL 和工艺库
read_verilog designs/src/gcd/gcd.v
read_liberty -lib platforms/nangate45/lib/NangateOpenCellLibrary_typical.lib

# 2. 层次展开 + 行为综合（变成逻辑网络）
hierarchy -top gcd
proc        # 展开 always 块（行为 → 逻辑）
opt         # 逻辑化简（技术无关优化）
fsm         # 状态机编码优化
memory      # 存储器展开

# 3. 调用 ABC 做逻辑优化 + 工艺映射（关键！）
abc -liberty platforms/nangate45/lib/NangateOpenCellLibrary_typical.lib \
    -script +strash;scorr;ifraig;retime;strash;dch;strash;map

# 4. 时序优化（用真实单元延迟再优化一次）
opt_clean

# 5. 输出门级网表
write_verilog results/synth/gcd.v   ← "artengen" 类概念：网表就是这么生成的
澄清你记不清的"artengen 生成网表"：综合输出网表的动作在 Yosys 里叫 write_verilog（写出门级网表文件）。你可能记的是工具链里某个"网表生成器"或 ABC 的某个生成命令——本质都一样：综合的最后一步就是把映射好的逻辑写成网表文件。不用担心术语记混，知道"网表 = 综合的输出、由 Yosys/ABC 生成"就够了。

ORFS 里综合的产物：results/…/1_synth.v（门级网表）+ reports/…/1_synth.stat.rpt（统计：用了多少单元、面积多大）。

五、网表是什么样子的

门级网表就是"用标准单元名 + 连线"写的 Verilog：

module gcd(clk, req_msg, req_val, …);
  input clk;
  // 用工艺库里的单元拼出来
  NAND2_X1 u1 (.A(n1), .B(n2), .ZN(n3));   ← 一个与非门
  DFF_X1  d1 (.D(n3), .CK(clk), .Q(n4));    ← 一个触发器
  INV_X1  v1 (.A(n4), .ZN(n5));
  …
endmodule

这段网表就是后面所有阶段（布局、布线…）的"输入零件清单"。综合阶段到此结束。

六、关键概念速查

概念大白话
RTL行为级描述（Verilog），综合的输入
门级网表结构级描述（用工艺库单元拼），综合的输出
ABC伯克利开源逻辑综合工具：布尔优化 + 工艺映射的数学引擎
AIGAnd-Inverter Graph，"与门+反相器"的统一图表示，ABC 优化时的中间形式
工艺映射（mapping）把逻辑"对齐"到工艺库的真实单元上
逻辑深度（levels）从输入到输出最多经过几级门——越深越慢
DFF / Latch触发器/锁存器，存状态的基本单元
SDC 约束时钟周期、输入输出延迟等"必须满足的法规"
面积 / 延迟权衡综合时要选：同样的功能，用大而快的门还是小而慢的门

八、常见疑问

Q1：综合和"逻辑综合""物理综合"有什么区别？

传统综合（我们这里讲的）只看逻辑和门延迟；物理综合还把布局的线延迟也考虑进来（更准但更复杂）。ORFS 的综合阶段是传统逻辑综合。

Q2：为什么输出网表里全是 NAND/INV，没有 AND/OR？

工艺库里 NAND/NOR 比 AND/OR 更快更小（晶体管少），映射器会优先选它们——所以网表看起来"反相门特别多"，这是正常的。

Q3：综合结果不满意（太慢/太大）怎么办？

先看综合报告（单元数、逻辑深度），再调：换综合策略（面积优先/延迟优先）、改 RTL（减少逻辑层级）、放宽时钟约束。平台里就是调"目标阶段+参数"重新跑。

Q4：3D 流程里也有综合吗？

有。TaiWei 3D 的第 1 道工序就是综合（综合 → 2D 布局规划 → …），只是它后面要再拆层做 3D。所以综合是 2D/3D 共用的第一步。
