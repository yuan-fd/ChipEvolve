# 🧠 为什么可以自演化？

> 统计方法凭什么优化芯片？AI 怎么学会经验？为什么不能只记成功？数据学得过来吗？—— 四个疑问逐个答（大白话）

> 当前产品边界：用户只有一个“Agent 自主 BO/GP 优化”入口。baseline 是闭环内部第 0 轮；顺序扫描和离线策略只用于论文对照实验，不是产品模式；浏览器不提交 Provider、API Key、搜索预算或参数范围。


## 一、先分清两件事：优化 vs 学会

> **打个比方：**"自演化"其实是两件不同的事拼在一起：
     ① **优化**（找更好的参数）—— 像经验调参方法调药方：试几种，看哪个效果好，往好的方向试。
     ② **学习**（积累经验）—— 像系统记录经验：把每次试的结果记下来，下次少走弯路。

有人可能会问："贝叶斯只是统计方法，不触及芯片底层"——**这个疑问问得很好**，但它不是缺陷，而是关键洞察：**优化和芯片底层原理本来就该分开**。调参数不需要懂晶体管的物理，只需要知道"这个参数组合 → 这个结果"的对应关系，就像试药不需要懂分子结构，只需要知道"这个药方 → 这个疗效"。


## 二、疑问一：贝叶斯/高斯过程凭什么优化芯片？

**常见的疑问：**高斯过程、贝叶斯只是统计方法，它不碰芯片底层的物理，为什么能当优化算法？

**答：因为芯片设计里"调参数"这件事，本质上就是一个"黑盒子寻优"问题。**

把 EDA 工具当成一个**黑盒子**：

```text
参数（利用率、核数、时钟…）──▶ [黑盒子：20 道工序的 EDA 流程] ──▶ 结果（面积、速度、功耗、DRC 错误…）
```

我们**不需要知道盒子里面怎么工作的**，只需要回答一个问题：**"下一组参数试哪个，最可能得到好结果？"**

高斯过程做的就是这件事，分三步（大白话）：

1. **画"地形图"**：根据已经试过的几组参数和结果，猜出整个参数空间的"结果地形"——哪里高（效果好）哪里低（效果差）；
2. **标出"没把握的地方"**：高斯过程天生会告诉你"这里我猜得准、那里我猜不准"（带误差带）；
3. **选"性价比最高"的点试**：既找效果好的地方（利用），也试没把握的地方（探索），这就是"期望改进（EI）"——数学上挑一个"可能好 + 值得试"的下一组参数。

> **关键：**它优化的对象是"参数和结果的关系"，不是芯片物理。芯片物理已经由 EDA 工具本身处理了（黑盒子里）。贝叶斯优化是公认的"昂贵黑盒函数寻优"的标准方法——EDA 一次跑几十分钟甚至几小时，正好是最典型的应用场景。

**为什么特别适合芯片设计：**跑一次完整流程很贵（时间+算力），所以不能像普通调参那样随便试几千次。贝叶斯优化的特长恰恰是**用最少的试验次数找到好参数**——这正是 EDA 需要的。


## 三、疑问二：AI 到底怎么"学会经验"？

**常见的疑问：**AI 怎么能学会经验呢？它又不是芯片专家。

**答：AI 学的不是"芯片知识"，而是"数据里的规律"。**它学的"经验"其实就是：

**"在什么情况下，用什么参数，得到了什么结果"**

这跟人类系统记录经验是一样的：

| 系统记录经验 | AI 存数据 |
| --- | --- |
| "上次 gcd 用 45% 利用率，DRC 487 个错误" | 一条观测记录（设计+参数+指标） |
| "60% 利用率面积更小但错误更多" | 两条记录对比出趋势 |
| "下次试 50% 应该不错" | AI 用统计模型外推建议 |

**它不需要"懂芯片"**，就像天气预报员不需要懂大气的每个分子——只要数据够多、规律存在，统计模型就能抓住趋势。芯片参数和结果之间确实存在规律（比如利用率越高面积越小、但布线越挤错误越多），AI 学的就是这个规律。


## 四、疑问三：为什么当前主线不用强化学习直接控制？

**常见的疑问：**用强化学习就行了吗？具体怎么用强化学习？

**先说明一点：**强化学习（RL）不是当前产品控制器。经典 RL 需要大量在线试错，既昂贵又容易把不同约束下的经验混在一起。v2 正式闭环使用可审计的 BO/GP；离线策略代码只保留为论文消融对照，不拥有执行权。

**RL 的三件套（大白话）：**

| RL 概念 | 大白话 | 在芯片设计里对应什么 |
| --- | --- | --- |
| 状态 State | "现在是什么情况" | 当前设计的设计名、工艺、已有指标（面积/时序/功耗…） |
| 动作 Action | "我做了什么决定" | 这次选的参数（利用率=50%、核数=16…） |
| 奖励 Reward | "做得好不好" | 结果指标的好坏（DRC 少、时序达标、功耗低 → 奖励高） |

**离线对照实验怎么用（不属于产品入口）：**

1. 把历史成功的任务整理成一条条"轨迹"：状态（这次设计+指标）→ 动作（参数）→ 奖励（结果好坏）；
2. 让一个"影子策略"（行为克隆模型）学习这个规律：**"看到这种状态，历史上高手选了哪些参数、结果不错"**；
3. 在冻结的数据集上比较它和 seeded-random、BO 的离线表现；
4. 它不能从网页发起任务，也不能向 Runtime 提交参数。

> **为什么不直接用经典 RL 在线学？**因为经典 RL 要"边试边错"，而芯片流程跑一次很贵，随便试错会浪费大量算力、还可能产生一堆垃圾结果污染知识库。所以用**离线方式**：只从已有的真实成功经验里学（离线 RL / 行为克隆），安全、可解释、可控——代码注释里明确写着"offline-only trajectory and shadow-policy baselines"。


## 五、疑问四：数据那么庞大，学得过来吗？

**常见的疑问：**数据那么庞大，学习得过来吗？

**答：不用学"全部数据"，因为平台根本不让全部数据进来——这是刻意设计，不是缺陷。**

平台的知识入库有一条**铁律（observed-only，只收真实观测）**：

- 成功结果以 observed fact 入库；失败、超时、硬约束不合格也作为 negative evidence 保存，避免系统只看赢家；
- 模型预测不能冒充观测，只有 Runtime 终态、原始报告摘要、artifact 哈希和上下文指纹能形成证据；
- 经验必须匹配 RTL、工艺、工具链和设计约束指纹，跨上下文时不能直接用于动作 warm-start。

而且**优化的对象不是所有设计**，而是有**指纹匹配**的相似设计——gcd 的经验只影响 gcd 类的任务，不会拿 3D 的经验去指导完全无关的设计。就像经验调参方法的笔记分门别类：感冒的经验记在感冒那页，不拿去治骨折。

> **数据量问题的真正答案：**贝叶斯优化和离线 RL 恰恰是**专门为"数据少而贵"设计**的方法。它们不追求"看遍所有数据"，而是"用最少的数据给出最好的下一步建议"。数据少不是问题，数据质量才是关键——这正是本平台"证据优先、宁缺毋滥"设计哲学的数学基础。


## 六、本平台实际用的方法（真实代码）

以上不是空谈，平台里这些方法都是真实实现的（可直接在代码里查到）：

| 方法 | 代码位置 | 大白话 |
| --- | --- | --- |
| 高斯过程回归 | optimization.py · GaussianProcessRegressorLite | 给"参数→结果"画地形图 |
| 多目标贝叶斯优化 | optimization.py · MultiObjectiveBayesianOptimizer | 同时考虑面积/时序/功耗多个目标，用 EI 选下一组参数 |
| 重复实验汇总 | closed_loop.py · summarize_replicates | 同一参数组合重复运行，报告中位数、IQR、范围和失败率 |
| 停滞诊断 | closed_loop.py · stalled_decision / diagnosis_packet | 连续三轮没有达到预登记门槛后停止搜索并定位阶段证据 |
| 因果检验 | causal_learning.py · factorial_interaction_report | 用受控 2×2 实验判断两个参数是否存在组合效应 |
| 规则撤销 | evidence_rag.py · revocation ledger | 新的 holdout 证据推翻旧规则后，让旧规则退出可执行检索 |
| 观测指纹 | contracts/learning.py · LearningObservation | 每条经验带设计/工艺/工具/指标指纹，可追溯 |

完整闭环：**重复 baseline → 高斯过程拟合 → BO 选择参数组合 → 硬门禁 → Runtime/OpenROAD 实测 → 重复统计 → 晋级或累计停滞 → 三轮停滞诊断 → 正负证据入库**。每一环都要求“预测不能写成观测”。


## 七、诚实说明：能做什么、不能做什么

| ✅ 它能做 | ❌ 它不能做（别指望） |
| --- | --- |
| · 在冻结约束下自主选择并验证参数组合<br>· 用最少试验次数找到好参数（省算力）<br>· 同时保留成功、失败和无改善经验<br>· 给每次决策保留参数、置信度、重复统计和证据引用 | · 发明新的电路结构（那不是后端参数环的任务）<br>· 把不同 RTL、工艺或时钟约束下的经验直接混用<br>· 保证一定比默认参数好（没有改善时必须如实报告并转诊断）<br>· 替代 EDA 工具本身（工具还是要真实跑） |

> **最后的大白话总结：**自演化不是“AI 说一个参数、人点一下按钮”。它是一个自动做实验的研究员：先在同一考试条件下重复测 baseline，再用 BO/GP 选择一整组参数，真实跑 OpenROAD，连续三轮没有进步就停下来查证据；得到的成功、失败和被推翻的规律都带来源保存。优化的是参数选择，EDA 工具仍负责芯片物理。
