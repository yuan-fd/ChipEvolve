# 📚 自演化系统：怎么认识、怎么用

> 经验是怎么存进图书馆的？AI 怎么越用越聪明？—— 大白话讲解 + 使用指南

## 一、先搞懂：什么叫"自演化"和"入库"

> **打个比方：**平台有个"学习系统"（AI）。它想把每次做芯片的经验都记下来，存在一个"图书馆"里。以后做新芯片时，学习系统翻翻图书馆，参考以前成功的做法，给出更好的建议——这就是**自演化**（越干越聪明）。

**"入库"**就是：把一次做芯片的完整经验（用了什么图纸、什么工艺、什么工具、结果指标如何）整理成一条标准记录，存进图书馆的过程。

为什么要这么麻烦？因为学习系统**只看真实成功的经验**——如果失败的任务也存进去，就会教坏学习系统。所以入库有一整套"质检"流程（下面讲）。

## 二、入库要走哪几步？（完整流程）

> ① 跑任务 → ② 点按钮 → ③ 验证 → ④ 写数据库 → ⑤ 学习系统使用

| 步骤 | 大白话 | 在哪里发生 |
| --- | --- | --- |
| ① 跑任务 | 在平台跑完一个真实任务（比如 3D 设计），得到结果 | Worker 后台 |
| ② 点按钮 | 在"Projects & Results"页面，找到这次成功记录，点"Collect verified run"（收集验证结果） | 网页（前端） |
| ③ 验证 | 系统检查：任务确实成功了？图纸指纹对得上？指标齐全？检查通过后打个"已验证"章 | 后台程序（analysis 包） |
| ④ 写数据库 | 把经验写进图书馆数据库（tenant-learning.db），生成一条带编号的"观测记录" | 数据库 |
| ⑤ 学习系统使用 | AI 翻图书馆，参考历史经验，给出下一步参数建议 | 后台程序（优化模块） |

## 三、怎么用：把经验存进图书馆（3 步）

1. **跑任务**：在 Backend 页提交 2D / 3D 设计任务，等它跑完；
2. **看结果**：在 Projects 页查看这次的版图、指标、产物；
3. **入库**：确认结果满意后，点"Collect verified run"——系统验证通过，经验就存进知识库了。

> **记住：**目前入库是**人工触发**的（点按钮），验证通过才会写入；失败任务、没验证的结果不会进库——这是"宁缺毋滥"的设计，保证 AI 学到的都是真经验。

## 四、当前状态

| 能力 | 状态 |
| --- | --- |
| 知识入库（验证 → 写库 → 编号） | ✅ 可用（实测一次成功） |
| 入库触发方式 | ✅ 人工触发（Projects 页按钮）；自动触发规划中 |
| AI 建议 | ✅ 可用：GP/BO 贝叶斯优化 + 行为克隆影子策略（bo-gp / rl-shadow / hybrid 三种） |
| 建议决策 | ✅ 人工确认：AI 只提建议，人拍板后参数才生效 |

## 五、怎么认识：记住三句话

- **自演化 = 记录经验 + 优化参数**：把成功经验存进图书馆（记录），AI 参考历史给出更好的参数建议（优化）；
- **质量 > 数量**：只有"真实跑成功 + 验证通过"的经验才入库，宁缺毋滥；
- **AI 是参谋，人是决策者**：AI 给建议，最终是否采用由人决定。

> **一句话：**跑任务 → 点收集 → AI 越用越聪明。就这么简单。
