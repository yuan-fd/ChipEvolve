一、这个平台到底是干嘛的？

打个比方：平台是一座 芯片设计工厂。你（用户）把设计图纸（RTL 代码）交给工厂，工厂里的机器（EDA 工具）自动把图纸变成真正的芯片版图（GDS 文件），最后还能告诉你这个芯片跑得快不快、费不费电、有没有毛病。

这工厂有三个特别的优点：

  • ① 全自动流水线：从图纸到成品，中间的几十道工序（综合、布局、布线……）机器自己跑，不用人盯着。
  • ② 每一步都留证据：每道工序做完都"拍照存档"（产物文件 + 哈希值），谁做的、用什么工具做的、结果什么样，全都查得到——这是它最值钱的地方。
  • ③ 会学习：工厂有个"学习系统"（AI 自演化系统），会把每次成功的经验存进"图书馆"（知识库），下次做新设计时参考，越做越好。

平台分两条"生产线"：

  • 2D 生产线：普通芯片（一层楼），已经非常成熟。
  • 3D 生产线（TaiWei）：立体芯片（上下两层楼叠起来），刚建好，是重点发展方向。

二、仓库目录树 —— 工厂的每个房间

整个工厂就在服务器的 ~/openroad-platform 这个文件夹里。里面的结构，就像工厂分了好几个车间：

openroad-platform/ ← 工厂大门
├── apps/ ← 前台接待处（用户看到的界面）
│ ├── api/ ← 前台电话总机：收订单、发指令的 Python 程序
│ └── web/ ← 橱窗：网页界面（index.html + 样式 + 脚本）
├── packages/ ← 工厂车间（核心干活的地方）
│ ├── contracts/ ← 订单合同格式：任务单长什么样（TaskSpec）
│ ├── scheduler/ ← 调度室：排队、安排工人、记录进度
│ ├── execution/ ← 车间机器：跑 EDA 工具（ORFS/TaiWei 等）
│ ├── analysis/ ← 质检+学习系统：分析结果、知识入库、AI 建议
│ └── visualization/← 照相室：把版图画成图片/SVG 给你看
├── integrations/ ← 外接设备库：各个插件（TaiWei 3D、RTLScout…）的说明文件
├── workflows/ ← 工艺手册：几种标准流程的说明书
├── scripts/ ← 杂务工具：验收脚本、启动脚本等
├── tests/ ← 质检员：自动测试（pytest）
├── var/ ← 档案室：所有产出的证据（设计/结果/数据库）——不许删！
├── docs/ plan/ knowledge/ memory_snapshots/ project_kb/
│ ← 会议室资料：文档、计划、知识、项目备忘
└── README.md ← 工厂简介

每个房间干什么（大白话）

房间（目录）白话解释打个比方
apps/api网站的后台程序，接收网页上点的每一个按钮电话总机
apps/web你看到的网页本身（六个页面）接待大厅
packages/contracts规定"订单单"和"设备说明"的标准格式合同模板
packages/scheduler把任务排进队列，安排工人（worker）执行，记录进度调度室
packages/execution真正去调用 EDA 工具干活（跑 OpenROAD/TaiWei）车间机器
packages/analysis分析结果、提取知识、给 AI 建议、做知识入库质检 + 学习系统
packages/visualization把版图/电路画成图片照相室
integrations每个插件（TaiWei 3D、RTLScout…）的"说明书+合同"外接设备库
var所有真实产出（设计文件、结果、数据库）档案室（最珍贵）
tests自动检查有没有弄坏东西质检员
提醒：var/ 是档案室，里面的东西（原始证据）永远不能删——那是整个平台的信用所在。

三、接口 —— 房间之间的电话线和门

网页和后台之间、后台和车间之间，靠 接口（API） 说话。接口就像"电话号码"，网页打某个号码，后台接起来干活，再把结果传回去。

① 网页 → 后台 的接口（都叫 /api/ 开头）

接口大白话谁在用
/api/auth/*登录、注册、退出（工厂大门登记）所有人
/api/designs/*查看/导入/生成设计图纸（RTL）Frontend 页
/api/runtime/runs/*提交 2D 任务、看进度、取消Backend 页
/api/extensions/taiwei/run提交 3D 任务（选工艺库/参数）Backend 页 3D 面板
/api/extensions/edacraft/*跑专业小工具（TCAD/SPICE 等）Extensions 页
/api/platform/results列出所有项目/结果Projects 页
/api/runtime/runs/<id>/collect-learning知识入库：把这次成功经验存进图书馆Projects 页按钮
/api/learning/observations查看已入库的知识Self-Evolution 页
/api/recommendations/*看 AI 建议、做决定Self-Evolution 页
/api/health体检：工厂各设备是否正常监控

② 后台 → 车间 的接口（内部约定）

后台把任务交给工人（worker）时，靠一张标准格式的 任务单（TaskSpec）：

{
  "task_id": "唯一编号",
  "plugin_id": "用哪台机器（orfs=2D / taiwei-pin-3d=3D）",
  "inputs":   { "rtl": 图纸文件(带哈希), "tech": 工艺库, "case": 设计名 },
  "parameters": { "core_utilization_pct": 利用率, "num_cores": 核数, ... },
  "timeout_seconds": 超时时间
}

工人拿到任务单 → 调对应的适配器（adapter） → 适配器去操作真正的 EDA 工具 → 把结果（GDS/指标/日志）交回来，存进档案室。

关键点：插件（TaiWei 3D 等）都是"插拔式"的——只要按 合同格式 写一个适配器，就能挂到工厂里，不影响别的车间。这就是"开放式平台"的意思。

四、多人协作 —— 大家一起干活怎么不打架

好几个人（同学、老师、你）一起在这个工厂干活，怎么保证不互相踩脚？工厂用了一套规矩：

① 版本管理（Git）—— 像"文档的历史记录"

  • 整个代码仓库有完整历史，每次改动都记一笔（谁、什么时候、改了啥）。
  • 大家各自在自己的"分支"上干活，改好了再合并到主线上（main），有问题随时退回。
  • 规矩：本地随便改，但 不推送到公共服务器、不随便部署——改完先让负责人（你）验收。

② 数据隔离 —— 各干各的，互不串门

  • 每个用户登录后有自己的"私人空间"（设计、任务、结果都按用户隔离）。
  • 你看到的是你的，他看到他的是他的；想共享要明确"打开共享"。

③ 证据优先 —— 谁也别吹牛

  • 谁说自己跑通了？——拿日志、拿文件、拿哈希值来。
  • 每句话标注是"事实"（有证据）还是"猜测"（没有），猜的必须说清楚。
  • 这就是防止"看起来成功了但其实没有"的护城河。

④ 约定俗成的工作流（新人入职流程）

1 领任务→ 2 建分支→ 3 改代码→ 4 写测试→ 5 跑全量回归→ 6 提交+说明→ 7 给负责人验收

验收不过（回归变差/没证据）就退回去改，不许带病上线。

开放贡献的意思：任何人（包括未来的新同学）都可以按这个流程加功能、修 bug、加插件。README 里会写清楚怎么加入——这是"开放式平台"的核心。

五、知识入库 —— 一次经验怎么变成"图书馆藏书"

这是学习系统（AI 自演化）的核心。工厂把每次成功经验存进"图书馆"（知识库），以后做新设计就能参考。走的是五道关：

① 产生→ ② 触发→ ③ 验证→ ④ 入库→ ⑤ 使用

逐关解释：

关卡大白话具体动作
① 产生 跑完一个真实任务，得出结果 比如跑完一个 3D 设计，得到 GDS 版图 + 一堆指标（面积/功耗/速度/错误数）
② 触发 有人按"收集"按钮 在 Projects 页点"Collect verified run"（注意：目前要手动点，机器不会自动存）
③ 验证 质检：这次结果是不是真·合格 检查任务确实成功了、文件哈希对得上、指标齐全 → 状态从"待验"变"已验证"
④ 入库 写进图书馆，贴好标签 存成一条"观测记录"：设计是什么 + 用哪个工艺 + 哪个工具版本 + 结果指标，全都有据可查
⑤ 使用 学习系统翻书给建议 AI 根据图书馆里的历史经验，用数学方法（贝叶斯优化等）建议下次怎么调参数

转换过程（原始数据 → 知识）

原始 run 数据
（日志/文件/指标）→ 导出器
（挑出有用的）→ 标准化观测
（带指纹+标签）→ 图书馆书架
（tenant_observations）→ AI 建议

目前发现的真实问题（大白话）：这条链路的"零件"都是好的（我实测手动点一下就能入库成功），但缺了"自动触发"这个环节——机器跑完任务后不会自己存，必须有人去点按钮。所以图书馆一直是空的，不是"入库失败"，是"没人去按按钮"。这属于"流程没接上"（架构问题），不是机器坏了。

六、一个原始数据走完全程 —— 从头到尾看一遍

我们拿"一个 3D 芯片设计"当例子，看它从进厂到变知识，完整走一遍：

第一步：图纸进厂

你上传一份 RTL 代码（芯片的"图纸"，就是一段文字代码，描述芯片怎么工作）。系统给它算一个指纹（SHA-256）——相当于给图纸盖了个钢印，证明"就是这张，没被换过"。

第二步：下生产单

你在网页上填：用哪个工艺（3D 工艺库）、利用率多少、几个核……系统生成一张任务单，排进队列。

第三步：车间干活（20 道工序）

工人（worker）领到任务单，开动 TaiWei 3D 机器，自动跑完 20 道工序：综合 → 布局 → 分层（上下两层楼）→ 布线 → 检查……每一步都留日志和中间文件。

第四步：出厂成品

最后得到一堆"成品"：GDS 版图文件（真正的芯片图形）、3D 视图图片（你眼睛能看的）、指标报告（面积多大、多快、多费电、多少个错误）。这些全存进档案室（var/），带钢印（哈希）。

第五步：经验入库

这次干得不错 → 点"收集"按钮 → 系统把这次的经验（设计 + 工艺 + 工具 + 指标）提炼成一条标准化知识，存进图书馆。

第六步：学习系统翻书

下次做新设计时，AI 翻图书馆，参考以前的成功经验，给你建议："上次 60% 利用率效果不错，这次试试 55%？"——这就是"自演化"：工厂越干越聪明。

七、这些东西有什么用 —— 一句话总结

一句话：这座工厂让"芯片设计"从"手工作坊"变成"自动化+会学习"——2D/3D 都能自动跑、每一步有证据、经验能沉淀、大家能一起干。你负责的 TaiWei 3D 就是把"立体芯片"这条新生产线建好，让后人（老师、同学、新成员）都能轻松用它、往里加东西。
