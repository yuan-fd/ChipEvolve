一、先分清两个名字：OpenROAD 和 ORFS 不是一回事

很多人（包括曾经的我）把这两个名字混着用，其实是两个层次的东西：

名字是什么类比
OpenROAD一个开源的EDA 工具引擎（C++ 写的单个程序）：能做综合、布局、布线、时钟树、时序分析、DRC 检查一台"多功能车间机器"
ORFS（OpenROAD Flow Scripts）一套流程脚本 + 设计 + 工艺库的完整仓库：把 OpenROAD 按正确顺序串成"RTL → GDS"流水线，还附带一堆现成设计和工艺文件"车间流水线的工艺手册 + 备料仓库"
记住一句话：OpenROAD 是机器，ORFS 是用机器的方式（以及配套的材料）。我们平台里说的"2D 工具链 ORFS + OpenROAD + Yosys"就是"用 Yosys 做综合、OpenROAD 做布局布线、ORFS 把它们串起来"。

二、OpenROAD 是什么？—— 开源的芯片"车间机器"

OpenROAD（github.com/The-OpenROAD-Project/OpenROAD）是一个开源、免费的芯片物理设计工具，目标是把"从门级网表到最终版图"的物理设计全流程自动化。它主要干这些活：

  • 综合（接 Yosys）：把 RTL 代码翻译成门电路网表；
  • 布局规划（floorplan）：定芯片多大、输入输出放哪、电源网络怎么铺；
  • 布局（placement）：把成千上万个标准单元摆到合适位置；
  • 时钟树（CTS）：把时钟信号送到每个触发器，保证同时到达；
  • 布线（routing）：用金属线把所有单元连起来；
  • 检查：DRC（设计规则检查）、时序分析（STA）、功耗分析。

它是个命令行工具（一个二进制文件 openroad），可以用脚本（Tcl）驱动，也可以跑别人写好的流程脚本（ORFS 就是）。

为什么它重要：传统商业工具（Cadence、Synopsys）贵且闭源；OpenROAD 开源免费，还能定制、能对接研究——所以学术界和我们的平台都用它。

三、ORFS 是什么？—— 把机器串成流水线的"工艺手册"

ORFS（OpenROAD Flow Scripts，github.com/ieee-ceda-datc/OpenROAD-flow-scripts）是 OpenROAD 官方配套的完整流程仓库，里面三样东西：

OpenROAD-flow-scripts/ ├── flow/ ← 流水线本体（Makefile 驱动） │ ├── scripts/ ← 每阶段的 OpenROAD Tcl 脚本（综合/布局/布线…） │ ├── designs/ ← 现成设计（gcd、aes、ariane、ibex…几十个） │ │ └── src/gcd/ ← 每个设计有自己的 RTL 和约束 │ └── platforms/ ← 工艺库（nangate45、asap7、sky130hd、gf180mcu…） ├── tools/ ← OpenROAD、Yosys 等工具源码 └── build_openroad.sh ← 一键编译脚本

它的用法很"傻瓜"——在 flow/ 目录里指定一个设计配置，跑 make 就从头跑到尾：

cd OpenROAD-flow-scripts/flow
make DESIGN_CONFIG=./designs/nangate45/gcd/config.mk   ← 一条命令，RTL 到 GDS 全流程
关键理解：ORFS 的价值不只是"脚本"，而是它把设计 + 工艺 + 流程打包成了可复现、可对比的标准环境——这也是它成为学术界事实标准的原因。我们的 3D 工具链用的 ORFS-Research 就是这个仓库的 3D 扩展版。

四、一条 RTL 怎么变成 GDS（六阶段，每阶段干什么）

① 综合 Synth→ ② 布局规划 Floorplan→ ③ 布局 Place→ ④ 时钟树 CTS→ ⑤ 布线 Route→ ⑥ 终检 Finish
阶段大白话输入 → 输出典型耗时占比
① 综合（synth）把"图纸语言"（RTL）翻译成"零件清单"（门电路网表）RTL + 工艺库 → 网表 netlist低
② 布局规划（floorplan）定芯片多大、长什么样：核心区尺寸、IO 引脚位置、电源网格网表 → 版图轮廓 + 电源网络低
③ 布局（place）把几万~几百万个标准单元摆进芯片，摆得下、不打架、好连线轮廓 → 带位置的版图中
④ 时钟树（CTS）把"心跳信号"（时钟）送到每个触发器，保证同时到达（建平衡树）版图 → 带时钟的版图中
⑤ 布线（route）用金属线把所有单元连起来（先全局后详细，还要过设计规则）版图 → 完全连通的版图高
⑥ 终检（finish）DRC 设计规则检查、时序签核、导出最终文件版图 → GDS 版图文件 + 指标报告中
注意：这里说的是"标准流程"。3D 流程（TaiWei）是另一套——它内部会先做一层楼的初步设计（相当于阶段①②），再拆成上下两层继续（分层、双 die 布局、3D CTS、跨层布线），一共 20 道工序。

五、关键名词速查表

名词大白话在流程里的角色
PDK / 工艺库芯片的"建材标准"（这家工厂用哪套规则造芯片）整个流程的根基
LEF单元的"外壳尺寸图"（每个零件多大、引脚在哪）布局布线时用
LIB / .db单元的"性能表"（每个零件多快、多费电）时序/功耗分析用
DEF设计的"摆放清单"（哪个单元放哪个坐标）布局阶段的输出
GDS / GDSII芯片的"最终图形文件"——能拿去制造的那种流程的最终产物
SDC时序约束（时钟多快、哪里必须准时）综合/时序分析的依据
CTS时钟树综合（见上）阶段 ④
Core utilization（核心利用率）芯片核心区被单元"占了多少面积"（高了挤、低了浪费）布局规划参数
Place density（放置密度）布局时单位面积放多少单元（和利用率类似，另一个视角）布局参数
WNS / TNS最差/总时序余量（负数 = 时序违例，芯片可能跑不到目标频率）时序报告
DRC设计规则检查（金属线间距够不够、孔对不对）终检
记不住也没关系：你只需要知道"利用率/密度/时钟周期"是主要旋钮，"GDS/指标/DRC"是主要产物，剩下的按需查这张表。

六、我们平台是怎么用 ORFS 的

平台把 ORFS 当一个插件挂进来（orfs 插件，能力标签 eda.rtl_to_gds），你不需要碰命令行：

网页上的参数对应 ORFS 流程里的东西
Clock port / Clock period（时钟端口/周期）SDC 约束的时钟定义（clock_period_ns）
Core utilization（核心利用率）布局规划密度（core_utilization_pct）
Placement density（放置密度）布局密度（place_density）
Target stage（目标阶段）跑到哪一步停（synth/floorplan/place/cts/route/finish）
PDK / platform用哪套工艺库（nangate45 / asap7…）

提交任务后，平台 worker 会：把参数翻译成 ORFS 能懂的配置 → 在隔离工作区跑 make 全流程 → 收集产物（GDS/DEF/网表/指标/日志）→ 每个文件算 SHA-256 存档 → 结果进数据库。你看到的就是：提交 → 六阶段进度条 → 版图 + 指标报告。

对我们研究的意义：因为 ORFS 是可复现的标准流程，我们的每一次运行都可以被任何人重跑验证——这正是平台"证据优先"的基础。想深入的同学直接去看 docs/tutorials/01_openroad_platform_overview.md 的目录树讲解。

七、想自己动手？从跑 gcd 开始

最经典的最小设计 gcd（最大公约数计算器），流程大约几分钟：

# 1. 装（服务器上通常已装好，这里给全新机器）
git clone --recursive https://github.com/ieee-ceda-datc/OpenROAD-flow-scripts
cd OpenROAD-flow-scripts
./build_openroad.sh --local   # 编译 OpenROAD + Yosys（约 1-2 小时）

# 2. 跑 gcd（nangate45 工艺）
cd flow
make DESIGN_CONFIG=./designs/nangate45/gcd/config.mk

# 3. 看结果
ls results/nangate45/gcd/base/          # 6_final.gds、6_final.def、报告…
cat reports/nangate45/gcd/base/6_final.gds 2>/dev/null   # 或用平台直接看渲染
建议：第一次跑如果报缺工具，先看 env.sh 和 README 的依赖要求（gcc、cmake、boost 等）。服务器上我们平台的 2D 工具链就是装好的 ORFS（~/OpenROAD-flow-scripts），3D 用的是 ORFS-Research 定制版（.tools/taiwei-official-3d）。

八、黑盒使用者常问的

Q1：我改了利用率/密度，结果会差多少？

利用率高 → 面积小但布线挤、时序容易差、DRC 多；利用率低 → 面积大但好布线。平台用批量并行模式（L1）可以一次跑多组参数对比，不用一个个试。

Q2：2D 和 3D 的关系？

两条独立流水线。2D 是 ORFS 六阶段；3D 是 TaiWei 20 道工序（内部自带 2D 预步骤）。不跑 2D 也能跑 3D，2D 结果可选作对比基线。

Q3：报错看不懂怎么办？

每个阶段都有日志文件（logs/ 下），平台后端页的进度条点开能看阶段事件。最常见的两类：工具链缺失（缺 LD_LIBRARY_PATH）和设计约束问题（时钟/面积配置不合理）。

Q4：OpenROAD 和商业工具的区别？

功能覆盖核心流程，但收敛性、先进工艺支持、易用性不如商业工具（Cadence/Synopsys）。它的优势是开源、可复现、可研究——我们平台就是建立在它之上的。
